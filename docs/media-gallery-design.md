# KPanel 图库设计

- 状态：本地候选（`claude/media-gallery`），未合入主线；正式状态以候选门禁、浏览器验收和发布记录为准
- 路由：`/gallery`（可带 `path=<绝对路径>` 与 `hostId=<集群主机>`）
- 入口：桌面模式独立图标“图库”（开始菜单同步出现）；文件管理顶部命令栏“图库”按钮以图库方式打开当前文件夹；
  经典模式不增加左侧主导航，与历史监控、进程管理器、系统中心一致
- 真源：宿主机上的普通文件夹；不建索引、不存数据库影子、不新增后端 API 或信任边界

## 1. 产品目标

让管理员把服务器当作一个安静的私人相册：上传照片和视频，按月份浏览，按相册整理，在沉浸式查看器里
看大图和播放视频。照片永远是普通文件——文件管理能看到、能移动、能备份，图库只是更好看的呈现方式，
删除和重命名也走文件管理同一条链路。

## 2. 数据模型

| 概念 | 落在宿主机上 | 说明 |
| --- | --- | --- |
| 图库位置 | 一个文件夹，默认 `/home/gallery` | 只保存在当前浏览器（`localStorage` `kpanel:gallery:v1`），不能是根目录 `/` |
| 照片/视频 | 文件夹里的文件 | 扩展名优先识别（宿主机 `mime.types` 不可靠），MIME 只补充未知扩展名；SVG 与点文件不算媒体 |
| 相册 | 图库位置的直接子文件夹 | 点开相册时同样展示它的直接子文件夹作为子相册 |
| 时间线 | 当前文件夹及其直接子文件夹中的媒体 | 按修改时间分月；“按名称”排序时不分组 |

读取边界（`web/src/lib/galleryLibrary.ts`）：每页 500 项，当前文件夹最多 10 页，最多汇总 48 个子相册、
每个相册最多 4 页，4 路并发；达到边界时界面明确提示“仅汇总了部分内容”。单个相册读取失败只跳过该相册并提示。
当前文件夹逐页显示，不等待后续页或手选封面读取；本窗口导航缓存保留 30 秒、最多 64 个文件夹和合计 10,000 项，
进入相册先展示已扫描内容，同时重新读取宿主机。切换主机及收到文件变更通知时清空缓存，迟到的取消响应不能写回。

## 3. 复用的文件链路

| 能力 | 复用接口 | 约束 |
| --- | --- | --- |
| 列表 | `GET /api/v1/files`（新增前端可选 `limit`，Agent 上限 500） | Session；`hostId` 走既有集群文件中继 |
| 缩略图 | `GET /api/v1/files/content?mode=thumbnail&version=` | Agent 仅缩放 JPEG/PNG/GIF（≤12 MB，320×210 框）；仅 413/422 或图片解码失败回退原图（≤16 MiB），限流不回退 |
| 原图/视频 | `GET /api/v1/files/content?disposition=inline` | Range 流式播放；视频画面不可解码时提示转码 |
| 上传 | `POST /api/v1/files/upload`（`overwrite=false`） | 2 路并发（对齐 Agent 上传闸门）；重名永不覆盖，自动改为 `name (2).ext` |
| 新建/重命名/移动/删除 | `POST /api/v1/files/actions` 的 `mkdir`/`rename`/`move`/`trash` | 删除只移入回收站；移动和删除都携带 `expectedResourceVersions`，移动不覆盖同名文件 |
| 下载 | 既有 `downloadFileEntries`（单文件票据、多文件 ZIP） | 与文件管理一致 |

图库改动后通过 `notifyFileDirectoriesChanged` 通知已打开的文件管理窗口；文件管理里的改动同样会让图库刷新。
图库图片共享 2 路请求队列，视频海报共享 1 路队列，保留后端原有读取与生成限额；429/503 最多重试 3 次，
单次图片调度后 20 秒截止、读取体积最多 16 MiB。离屏图片撤销未完成请求并释放显示租约，近期按版本命中的小图可直接复用对象 URL；
每个图库页面最多保留 96 项、16 MiB 编码数据及 64 MiB 估算解码数据，单图编码数据超过 4 MiB 不保留，60 秒到期清理；
容量压力按最近使用顺序淘汰闲置项，仍显示中的图片持有安全租约，待离屏再释放，因此活跃视口不计作可强制回收的缓存额度。
切换主机、文件变更事件及页面关闭会清理缓存，迟到旧请求不能重新写回。顶部大图保持既有清晰度策略，不新增持久缓存。
查看器另保留最近 3 张有版本且已知不超过 4 MiB 的原图，受 8 MiB 编码数据、32 MiB 估算解码数据和 60 秒时效约束；超限按 LRU 淘汰，解码尺寸过大不保留。
大图/未知大小原图继续原生加载，不预取邻近原图；当前原图排在等待中的缩略图之前，不增加请求并发；有界读取失败时退回原生加载与既有重试。关闭查看器立即取消请求并释放其缓存，文件版本或来源改变后重新读取。

## 4. 呈现

- 顶部封面：最新一张原图 ≤12 MB 的照片铺满并加底部暗化（没有时才用缩略图），标题、统计（照片/视频/相册/体积）、路径与主要操作。
- 相册：4:3 封面卡片，封面优先最新静态照片；卡片菜单提供重命名、在文件管理中打开、删除。
- 封面可手动指定：在相册文件夹里写一个隐藏的小文件 `.kpanel-cover.json`（`{"version":1,"cover":"<相对路径>"}`），指向该文件夹内（页面封面可再深一层）的一张静态照片；
  不新增后端接口，经普通文件上传覆盖写入，随文件夹一起备份、移动。入口：查看器顶栏"设为封面"（可选"该相册"或"当前页面"，再点已是封面的选项恢复自动）、
  封面菜单的"更换封面"（点选一张）与"恢复自动封面"。标记指向的照片被删除、改名或标记损坏时静默回退到自动封面；视频和浏览器不能直接显示的格式不能作封面。
  封面上的文字叠加了更强的左侧暗化、图片整体压暗和文字投影，亮色或带文字的封面仍保持 ≥4.5:1（标题大字 ≥3:1）的最坏情况对比度。
- 工具栏（随页面滚动，不吸顶；选择模式的操作条才吸顶）：全部/照片/视频分段、文件名搜索、最新/最早/名称排序、紧凑/标准/舒展三档密度、选择模式。
  触屏长按图片约 0.4 秒进入连续选择，滑过图片可扩展或收缩范围；起点原本已选中时连续取消。
  已在选择模式时横向滑动也可开始范围操作；未长按的纵向手势保持原生滚动。连续选择靠近上下边缘自动滚动，松手或取消后停止，抑制拖动后的误点。
- 时间线：方形网格，每月第一项在 ≥5 项时以 2×2 精选块呈现（精选块优先用 ≤12 MB 原图保证清晰）；
  视频及相册视频封面共用按需取帧逻辑，明确 seek 到 `min(1 秒, 时长/3)` 并等待目标帧后，截成 ≤640px 的 JPEG 海报并释放播放器；
  海报按主机来源、文件路径和版本缓存在本标签页，最多 240 张且编码字符串预算 12 MiB。取帧单次 12 秒截止，失败最多再尝试 2 次；
  查看器打开或桌面窗口非活动时暂停新的取帧工作。悬停 0.4 秒才重新挂载静音预览，角标显示时长；
  浏览器无法显示的格式（HEIC/TIFF 等）显示格式占位，查看器提供下载。渲染按 240 项分批追加。
- 查看器：深色沉浸背景（当前图模糊环境光）、缩略图先显示再淡入原图、滚轮/双击/按钮缩放与拖动平移、
  当前原图完成后才预热相邻缩略图，不再提前下载相邻原图；节省流量、慢速网络或相邻原图 >2 MiB 时跳过预热。
  左右键与横向滑动翻页、`i` 详细信息、`Delete` 移入回收站、全屏。顶栏、翻页箭头和底部缩略图条悬浮在照片之上，
  触屏支持双指缩放（1–6 倍）和单指平移，平移限制按实际图片尺寸计算；未缩放时横滑跟手，斜滑和双指手势不触发翻页，首尾保留阻尼反馈。视频保留原生触屏控件。
  不占用照片区域；约 2.8 秒无鼠标移动、按键或焦点变化后淡出，任意移动或按键（箭头翻页除外）即恢复，指针停在控件上或焦点在控件内时保持，
  触屏点按照片切换显隐；顶栏的“缩略图条”按钮可彻底关闭胶片条，选择保存在图库偏好 `filmstrip` 中。经典模式覆盖视口，
  桌面窗口内只覆盖该窗口。
- 移动到其他相册：选择模式的"移动到…"与查看器顶栏"移动到相册"打开文件夹选择器（从当前页面所在位置开始，只能在图库文件夹内向上，
  图库位置之外则从 `/` 开始；隐藏文件夹不列出；可在当前层级就地新建相册并进入），确认后调用既有文件 `move` 动作，目标是所选文件夹，
  每个文件单独返回成功或失败。同名文件不覆盖（"目标已存在"），部分失败时已成功的项移走、失败的项保持选中并列出首个原因。
  成功后页面立即把文件挪到新位置并重算相册计数与封面（不等重新读取），随后静默刷新；已经在目标文件夹里的文件不会被发送。
  也可以把时间线里的照片直接拖到相册卡片或页头路径里的上级文件夹上（拖动已选中的照片会带走整个选择，未选中的只带走这一张），
  只接受从本页同一主机发起的拖动；触屏没有拖放，用对话框。不跨主机移动。
- 主机切换：使用全站统一的主机选择器（`components/common/HostSwitcher.vue`，文件管理、图库、历史监控共用："当前主机" 按钮 + 可搜索、可键盘导航、带状态圆点的主机列表），位于页头路径下方；
  只有一台主机时不显示。可浏览的主机（与文件管理同一套判断，`lib/fileHostStatus.ts`）直接切换，进入目标主机自己的图库文件夹，不沿用当前路径；
  "文件代理未就绪"的主机跳到集群页处理；仅配对、没有文件中继的 Panel 在新标签页打开它自己的图库页。已排队的上传仍保存到它启动时所在的主机。
- 上传：拖入整页出现投放层；右下角上传队列显示整体与单项进度、取消、失败重试；非媒体文件跳过并提示。

视觉遵守 [`ui-visual-language.md`](ui-visual-language.md)：最小字号 12px（时长角标、计数），正文与按钮 14px；
圆角只用语义 Token；查看器的固定深色调色板只在查看器内部定义。

## 5. 已知边界

- 图库位置按浏览器保存，换浏览器需要重新设置（默认位置一致时无需设置）。
- 时间线使用修改时间而非 EXIF 拍摄时间；Agent 缩略图上限为 320×210，在高 DPI 屏幕上普通网格略软，精选块用原图。
- 远端主机（`hostId`）复用文件中继，受其限流约束；可从文件管理入口或图库页头的主机按钮进入。图库位置是一个路径，在每台主机上指向各自的同名文件夹：
  从远端文件栏（停在 `/` 时）打开，会进入该主机自己的 `/home/gallery`，页头显示主机名，空库时可创建，但“更改图库位置”只在本机提供（该设置属于当前浏览器）。
- 经典模式双栏文件管理里，每个栏的“图库”按钮读取该栏当前的主机与目录并整页打开图库（离开双栏页），浏览器后退会回到原双栏布局；
  它不会读取另一栏的内容，也不提供两栏之间的图库互传（互传仍用文件管理的双栏拖拽）。
- 移动只在同一台主机内进行；跨主机搬运仍用文件管理的双栏。被移走的照片如果正是某个文件夹的手选封面，该文件夹静默回到自动封面（标记文件不会自动改写）。
- 不做人脸/地点识别、不修改媒体元数据；适屏预览是可删除、可重建的有界派生缓存。

### 大图渐进加载

- 大于 256 KiB、至多 12 MiB 的 JPEG/PNG 使用版本绑定的 `mode=preview`：最长边 1440、解码上限 2400 万像素、不放大源图，JPEG 保留方向而不复制其余 EXIF。动画 GIF/APNG、其他浏览器格式、小文件及旧 Agent 失败回退继续读原图。
- 查看器先显示网格缩略图，再显示预览；按钮、滚轮、双击或触摸放大才请求原图，加载期间保留预览。原图失败保留预览并允许重试。下载继续使用原文件。
- 查看器独立保留至多 3 张预览、编码 6 MiB、估算解码 24 MiB、单张 2 MiB、60 秒；与原图缓存分别计额，关闭即释放。邻图按顺序预取，版本 URL 复用进行中的请求；省流/慢速连接禁用预取，离开相邻范围或关闭取消进行中的工作。
- Agent 预览内存仍至多 8 MiB、单张 2 MiB。Linux 完整 Agent 和轻量节点在各自受保护的状态目录下保存 `gallery-previews-v1`：目录 0700、文件 0600，至多 256 MiB/512 条、单张 2 MiB；30 天未访问的项在读取、写入或启动时清理，LRU 淘汰。磁盘配额计入文件头，原子发布临时文件额外至多一项。生成规格、文件路径和资源版本共同绑定缓存；读取校验摘要，损坏、只读、权限不符或第二进程占锁时回退内存/重新生成，缓存不需备份和数据迁移，旧版本可忽略该目录。原图读取和版本校验仍在缓存之前，文件变更或删除不能由旧缓存掩盖。缓存目录使用 `os.Root` 限定所有 I/O；非 Linux 平台保持内存模式。
- JPEG/PNG 的网格缩略图成功返回时，至多 16 个（含正在执行）预览任务可按需预热；最后一张需预热的缩略图返回后等待 250 毫秒再生成，减少网格加载时的 CPU 竞争，用户主动打开立即唤醒并跳过等待。同版本请求合并，用户打开的图片优先于等待中的预热，满队列允许置换尚未开始的预热。队列只存元数据，启动后才打开原图，单 worker、共用缩略图并发门、每个执行任务 20 秒超时；关闭服务取消并等待 worker 释放文件。同步解码不能中途打断，仍由原有 12 MiB/2400 万像素上限约束。无任务时无常驻 worker，不扫全盘，不是 Immich 的导入时全库生成。首次未预热照片仍有生成成本，预热会增加短时 CPU 与缓存磁盘 I/O。
- Panel 对成功、版本绑定预览允许 private 一小时缓存；失败和原文件仍 no-store。无数据库、新依赖和媒体源文件改写。该缓存只保存可丢弃预览，回滚代码无需还原原图或缓存数据。
